## Data architecture and migration

An additive, versioned SQLite migration creates:

- `creature_profiles`: stable key, scientific identity, structured record, reviewed-record protection.
- `pronunciation_assets`: generated audio identity, source signature, provider/voice/speed and generation metadata, separate from scientific records.
- `library_asset_issues`: missing/invalid legacy metadata and requested missing pronunciations for maintenance.
- `creature_game_rules`: the existing fictional game rating captured by persistent numeric creature ID, separate from biological facts. Renaming a displayed creature cannot silently change its game rating.
- `library_migrations`: schema version; a newer database is not silently downgraded.

Existing creature rows/IDs, custom fields, model directories and narration caches are retained. Legacy editorial profiles are bootstrapped once as **unverified**, never promoted automatically. Duplicate or unsupported legacy records are reported for review rather than deleted. Numeric IDs are stable within an installation; `stable_key` is the portable identity used to match imports across edits. Do not rename it when correcting a display label.

The legacy API category `marine_reptile` means the **Prehistoric Ocean adventure route**, not a taxonomic assertion. `taxon_group` explicitly distinguishes marine reptiles from `other_marine` aquatic animals. Pterosaurs cannot be imported into the dinosaur category. This iteration adds no unreviewed extinct-shark or other-marine candidates just to meet a quota.

## Repeatable curation workflow

From the repository, using the supported environment (Python 3.14 on Ubuntu 26.04):

```bash
.venv/bin/python scripts/library.py export --output /tmp/creatures-for-review.json
.venv/bin/python scripts/library.py schema --output /tmp/creature-schema.json
# Review actual references and edit a copy of the exported records.
.venv/bin/python scripts/library.py validate /path/to/reviewed-creatures.json
.venv/bin/python scripts/library.py import /path/to/reviewed-creatures.json
.venv/bin/python scripts/library.py audit --output data/library_audit.json
```

The document envelope is `{"schema_version": 1, "creatures": [...]}`. `--db /path/to/database.sqlite3` selects a different database; default is the app's configured database. Back up `data/` first. Validation/import are offline and do not make paid calls. Keep reviewed source JSON and attribution alongside any licensed assets in a reviewed change; generated audio belongs only in ignored persistent storage.

Required record structure is generated by the `schema` command. Important rules:

- Unique stable keys, explicit positive IDs when supplied, and unique scientific identities; conflicts abort the transaction rather than renumbering existing creatures. Omit `id` for a new record or a portable-key match where another installation may have a different number.
- Length ranges use metres (`m`), weight ranges kilograms (`kg`). Both endpoints are positive numbers with source IDs, or both are null. Unknown never becomes zero. Unsupported or reversed ranges are rejected.
- Store subcategory, taxon rank/group, period/modern status, habitat/distribution, diet, physical traits, offense/defense, description and three facts. Unreviewed fields stay null/empty, not invented.
- `verification_status=verified` requires reviewer/date, reviewed source URLs with field-level `supports`, explicit taxonomy/context and three supported facts. Validation checks provenance structure, **not the truth of a web page**. A human must actually inspect credible evidence before setting the flag.
- Verified profiles are protected from later automated imports. Independently verified pronunciation and reviewed artwork are also preserved when an otherwise unverified profile is updated. Corrections to protected information require an explicit maintainer-reviewed data migration, not a blind repeat import.
- Discovery tags (`giants`, `fast_swimmers`, `armored`) require a scientifically reviewed profile and supporting sources. Carnivore/herbivore discovery trails use reviewed diets. Empty trails say that reviewed entries are pending; the app does not fabricate speed rankings.

Unknown measurements appear in the audit as informational gaps. They do not require a curator to invent estimates to complete an otherwise reviewed record. Artwork, source, facts and pronunciation gaps remain explicit blocking issues.

## Licensed image workflow

No species images were downloaded in this change because access to source/license pages was blocked. Current SVGs are visibly labeled **Illustration placeholder**, never presented as identified paleoart. Existing raw `image_reference` fields are retained, but uncredited legacy images need reviewed attribution before becoming approved profile artwork.

For each future image, inspect the taxon identification, creator and license on the original source page. Prefer authentic living-shark photos and informed extinct-animal reconstructions. A museum page is not permission to redistribute. Supported explicit reuse records are CC0, Public Domain, CC BY 3.0/4.0 and CC BY-SA 3.0/4.0. Unknown/restrictive licenses are rejected. Preserve the actual license terms and model/source attribution; the validator does not grant rights.

Download an approved original deliberately, then optimize it offline:

```bash
.venv/bin/python -m pip install -r requirements-media.txt
.venv/bin/python scripts/prepare_image.py /path/to/original.jpg /path/to/image-credit.json \
  --key reviewed-taxon --output /tmp/prepared-image.json
```

The input credit JSON follows the schema's `Image` model. Set `placeholder:false` and include a safe provisional `/static/creatures/pending.webp` path, `creator`, `original_source_url`, supported `license`, `license_url`, full `attribution`, `modifications`, exact `identified_taxon`, `verified_by` and `checked_on`. The original source URL should identify the credited work, not merely a search page. `identified_taxon` must match the record's scientific identity; an unrelated species is rejected.

The helper normalizes EXIF orientation, removes metadata, preserves aspect ratio and saves local WebP widths up to 320/640/960 without upscaling. It writes atomically and returns the final image metadata. Merge that `image` object into the reviewed record and validate/import it. Pillow is needed only for image preparation/import validation, not normal app startup. `requirements-dev.txt` includes media dependencies for the full test suite.

The same shared image renderer handles selection, encyclopedia, profile, story, bracket and champion; it uses local responsive variants and lazy loading. There is no external image request during normal browsing and no bulk startup image download. Broken or unapproved artwork uses the labeled project placeholder. Image credits are available in the profile's source section and Settings → Image credits & library audit.

## Verified pronunciation research and bulk generation

Preferred references are actual museum/educational pronunciation guidance, including the sources listed in the request. Multiple accepted English variants can be retained. Existing AI/editorial respellings are **unverified**; a syntactically valid URL or generated voice output is not pronunciation verification.

A pronunciation record has `phonetic`, explicit `stress`, preferred `tts_text`, inspected `source_url`, `checked_on`, `verified_by`, `alternatives`, and status. Only `status:verified` with all evidence fields can enter bulk generation. Generate original audio from the guidance; do not download/reuse museum recordings without a separate explicit reuse license.

```bash
.venv/bin/python -m pip install -r requirements-audio.txt
.venv/bin/python scripts/setup_audio.py kokoro
bash GENERATE_PRONUNCIATIONS.sh --provider kokoro --voice af_heart \
  --report data/pronunciation_report.json
# Optional alternate local provider after its model is available:
bash GENERATE_PRONUNCIATIONS.sh --provider piper --voice en_US-lessac-medium
```

`BBS_VENV` selects the environment, as with START_APP.sh. `--db` selects the database, `--speed` sets generation pacing. Defaults can use `BBS_PRONUNCIATION_PROVIDER` / `BBS_PRONUNCIATION_VOICE`; otherwise Kokoro is preferred and the other available local provider can be used. A single bounded worker generates one name at a time. For the first large batch on an older laptop, stop the app to avoid competing with narration in another process, then restart after generation.

The command reports generated, reused, unverified and failed IDs. It skips unverified guidance even if a plausible respelling exists. Source metadata is validated again before synthesis. Cache identity includes TTS text, effective provider/model/runtime, voice and generation speed. Repeat runs reuse current WAVs. Source-credit/date changes with unchanged TTS text can refresh metadata without regenerating the waveform. Audio paths and provider/model/source/timing metadata are stored separately in SQLite. Files are written and published by the existing atomic cache system in `data/audio_cache/pronunciation/`.

Paid OpenAI generation requires **both** deliberate `--provider openai --allow-paid` and the existing explicit server enablement/key. It is never an automatic fallback. Browser speech cannot produce the required persistent files and is not used by this utility.

## Child speaker behavior

When the library loads, ready file URLs are attached to creatures; no TTS job is submitted. On a speaker tap, HTML audio directly plays that local URL inside the user gesture, stopping the previous pronunciation/narration. Selected prepared voice variants are preferred; otherwise an existing prepared local variant is used. Speed changes use playback rate and do not synthesize new audio. No hundreds-of-files audio preload is performed.

A missing/unverified file gives a calm message and a labeled written guide, with no on-demand local TTS, browser synthesis or external API call. The audit always records missing coverage; a stale file request also creates a maintenance issue. Regenerate verified assets deliberately after clearing the audio cache. Parent-only voice-preview controls may still generate an explicit test sample; they are separate from creature browsing and do not certify a name's pronunciation.

## Encyclopedia and tournament behavior

The home screen has an independent creature-book entry. Category/featured search does not start or reset a tournament. A creature picture opens a mobile profile with image, name/speaker, scientific identity, description, measurements, period, habitat/distribution, diet, facts and adaptations. Unknown/unreviewed content is labeled. Add to Tournament works in the compatible selection world; it cannot mix land/ocean picks or silently replace another world's active selection.

Outcome ratings remain fictional game rules stored separately by creature ID. Verified biological facts/adaptations can be passed to the story context and a reviewed fact can appear as an educational aside. Unreviewed claims are excluded from that context; generated stories never update canonical records. Winner reveal and seven-battle progression remain unchanged. No narration-speed optimization is part of this work.
