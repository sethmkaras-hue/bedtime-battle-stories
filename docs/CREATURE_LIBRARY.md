## Data architecture and migration

An additive, versioned SQLite migration creates:

- `creature_profiles`: stable key, scientific identity, structured record, reviewed-record protection.
- `pronunciation_assets`: generated audio identity, source signature, provider/voice/speed and generation metadata, separate from scientific records.
- `library_asset_issues`: missing/invalid legacy metadata and requested missing pronunciations for maintenance.
- `creature_game_rules`: the existing fictional game rating captured by persistent numeric creature ID, separate from biological facts. Renaming a displayed creature cannot silently change its game rating.
- `library_migrations`: schema version; a newer database is not silently downgraded.

Existing creature rows/IDs, custom fields, model directories and narration caches are retained. Legacy editorial profiles are bootstrapped once as **unverified**, never promoted automatically. Duplicate or unsupported legacy records are reported for review rather than deleted. Numeric IDs are stable within an installation; `stable_key` is the portable identity used to match imports across edits. Do not rename it when correcting a display label.

The legacy API category `marine_reptile` means the **Prehistoric Ocean adventure route**, not a taxonomic assertion. `taxon_group` explicitly distinguishes marine reptiles from `other_marine` aquatic animals. Pterosaurs cannot be imported into the dinosaur category. This iteration adds no unreviewed extinct-shark or other-marine candidates just to meet a quota.

## Repeatable curation workflow

From the repository, using the supported environment (Python 3.14 on Ubuntu 26.04):

```bash
.venv/bin/python scripts/library.py export --output /tmp/creatures-for-review.json
.venv/bin/python scripts/library.py schema --output /tmp/creature-schema.json
# Review actual references and edit a copy of the exported records.
.venv/bin/python scripts/library.py validate /path/to/reviewed-creatures.json
.venv/bin/python scripts/library.py import /path/to/reviewed-creatures.json
.venv/bin/python scripts/library.py audit --output data/library_audit.json
```

The document envelope is `{"schema_version": 1, "creatures": [...]}`. `--db /path/to/database.sqlite3` selects a different database; default is the app's configured database. Back up `data/` first. Validation/import are offline and do not make paid calls. Keep reviewed source JSON and attribution alongside any licensed assets in a reviewed change; generated audio belongs only in ignored persistent storage.

Required record structure is generated by the `schema` command. Important rules:

- Unique stable keys, explicit positive IDs when supplied, and unique scientific identities; conflicts abort the transaction rather than renumbering existing creatures. Omit `id` for a new record or a portable-key match where another installation may have a different number.
- Length ranges use metres (`m`), weight ranges kilograms (`kg`). Both endpoints are positive numbers with source IDs, or both are null. Unknown never becomes zero. Unsupported or reversed ranges are rejected.
- Store subcategory, taxon rank/group, period/modern status, habitat/distribution, diet, physical traits, offense/defense, description and three facts. Unreviewed fields stay null/empty, not invented.
- `verification_status=verified` requires reviewer/date, reviewed source URLs with field-level `supports`, explicit taxonomy/context and three supported facts. Validation checks provenance structure, **not the truth of a web page**. A human must actually inspect credible evidence before setting the flag.
- Verified profiles are protected from later automated imports. Independently verified pronunciation and reviewed artwork are also preserved when an otherwise unverified profile is updated. Corrections to protected information require an explicit maintainer-reviewed data migration, not a blind repeat import.
- Discovery tags (`giants`, `fast_swimmers`, `armored`) require a scientifically reviewed profile and supporting sources. Carnivore/herbivore discovery trails use reviewed diets. Empty trails say that reviewed entries are pending; the app does not fabricate speed rankings.

Unknown measurements appear in the audit as informational gaps. They do not require a curator to invent estimates to complete an otherwise reviewed record. Artwork, source, facts and pronunciation gaps remain explicit blocking issues.

The helper normalizes EXIF orientation, removes metadata, preserves aspect ratio and saves local WebP widths up to 320/640/960 without upscaling. ## Verified pronunciation research and bulk generation

Preferred references are actual museum/educational pronunciation guidance, including the sources listed in the request. Multiple accepted English variants can be retained. Existing AI/editorial respellings are **unverified**; a syntactically valid URL or generated voice output is not pronunciation verification.

A pronunciation record has `phonetic`, explicit `stress`, preferred `tts_text`, inspected `source_url`, `checked_on`, `verified_by`, `alternatives`, and status. Only `status:verified` with all evidence fields can enter bulk generation. Generate original audio from the guidance; do not download/reuse museum recordings without a separate explicit reuse license.

```bash
.venv/bin/python -m pip install -r requirements-audio.txt
.venv/bin/python scripts/setup_audio.py kokoro
bash GENERATE_PRONUNCIATIONS.sh --provider kokoro --voice af_heart \
  --report data/pronunciation_report.json
# Optional alternate local provider after its model is available:
bash GENERATE_PRONUNCIATIONS.sh --provider piper --voice en_US-lessac-medium
```

`BBS_VENV` selects the environment, as with START_APP.sh. `--db` selects the database, `--speed` sets generation pacing. Defaults can use `BBS_PRONUNCIATION_PROVIDER` / `BBS_PRONUNCIATION_VOICE`; otherwise Kokoro is preferred and the other available local provider can be used. A single bounded worker generates one name at a time. For the first large batch on an older laptop, stop the app to avoid competing with narration in another process, then restart after generation.

The command reports generated, reused, unverified and failed IDs. It skips unverified guidance even if a plausible respelling exists. Source metadata is validated again before synthesis. Cache identity includes TTS text, effective provider/model/runtime, voice and generation speed. Repeat runs reuse current WAVs. Source-credit/date changes with unchanged TTS text can refresh metadata without regenerating the waveform. Audio paths and provider/model/source/timing metadata are stored separately in SQLite. Files are written and published by the existing atomic cache system in `data/audio_cache/pronunciation/`.

Paid OpenAI generation requires **both** deliberate `--provider openai --allow-paid` and the existing explicit server enablement/key. It is never an automatic fallback. Browser speech cannot produce the required persistent files and is not used by this utility.

### Sources and evidence

PBDB official API supplies exact accepted fossil taxa, parent classification and recorded fossil intervals. GBIF's official species-match API supplies exact accepted Animalia identities (especially sharks). Synonyms, fuzzy matches and ambiguous scientific identities are refused. Fossil intervals and localities are labeled as source observations, not exhaustive lifespan or geographic claims. NHM genus pages have conservative labeled-fact and pronunciation parsers; HTML retrieval is **opt-in** after publisher terms review. Unsupported page layouts are queued rather than guessed.

AMNH, Smithsonian and Florida Museum are useful manual authorities, but do not yet have dedicated automatic fact adapters. Usborne and other educational references can be researched manually; `--pronunciation-index path.json` accepts a mapping of exact scientific names to approved educational page URLs within the importer’s source allowlist. This enables the labeled-guide parser, not unrestricted scraping. Alternate accepted variants can be retained in the existing pronunciation record. No third-party recording is downloaded. Missing guidance stays unverified.

Requests use HTTPS, an identified user agent, robots checks, per-host pacing, bounded retries/backoff and Retry-After handling. Inaccessible robots policies fail closed. Redirects remain within explicit scientific/media hosts. There is no access-control workaround. APIs and sites may change terms or schema; inspect their current policies before use. Set `BBS_IMPORT_USER_AGENT` to include your contact if required by a publisher. Sources that cannot be fetched appear in the review queue with links/issues.

Commons acquisition searches its API directly using the scientific name. Wikidata is optional (`--use-wikidata`), and access failure never prevents Commons search. A filename is insufficient: the file description must establish the requested taxon as its subject, with suitable image-medium evidence and reusable license/creator metadata. When optional structured depicts evidence is present and contradicts the taxon, the candidate is queued. Living sharks require photographic evidence; extinct candidates require reconstruction/paleoart evidence. Fossils and incomplete/uncertain identification are queued. Supported licenses remain CC0, Public Domain, CC BY and CC BY-SA 3.0/4.0. Preserve attribution and license obligations; Settings → Image credits lists approved artwork.

Up to two supported candidates per creature are downloaded into quarantine and converted to a preview, with a 20 MB transfer and 25 megapixel decode limit. An adult selects the image before publication. Approval verifies the original checksum and produces local responsive WebP assets. Remote search results never become child-facing images merely because their names match.

### Review, expansion and storage

Settings → Parent content review requires the configured passphrase. Sessions expire after 15 minutes; writes also require same-origin requests, a session CSRF token and explicit confirmation. Adults may approve supported facts, edit and approve evidenced pronunciation guidance, approve a downloaded licensed image, or reject the proposal. Partial approvals remain incomplete; they do not certify the whole profile. Reviewed fields are protected on later imports. Approving guidance does not itself generate audio: run the bulk command above. Child speaker taps only play existing prepared files.

Full mode discovers accepted PBDB taxa toward 150 dinosaur genera, 60 shark species and 40 marine genera. New identities are deduplicated and staged for review, never added just to inflate counts. Habitat, modern status and other unsupported biological fields require research before tournament eligibility or whole-profile verification. The targets are goals, not a promise that every needed field can be automatically sourced. An adult can reject unsuitable or outdated candidates.

Importer state, checkpoints, HTTP cache, quarantined originals and previews live under `data/importer/` (`BBS_IMPORT_DIR` overrides the default; configure the web app and CLI consistently). Parent credentials are stored there with restrictive permissions. SQLite backups are made under the database’s `backups/` directory before import/review changes. Existing audio remains under `data/audio_cache/`; approved images under `static/creatures/`. Back up these together. Do not commit these private/generated artifacts. Database locks cover short writes rather than network retrieval; imports can run while the app serves requests. Bulk audio may compete with narration for CPU, so schedule it outside story time.

Allow several GB for caches, originals, WebP variants and backups, in addition to the audio models/packages. A pathological 250-creature batch with two 20 MB originals per creature can require over 20 GB because HTTP caching and quarantined originals both retain copies. Actual usage depends on source sizes and backup retention. Keep backups deliberately; remove old backups/caches only after stopping imports and saving the reviewed library. Do not remove quarantined originals for pending image proposals: approval needs their checksum-verified bytes.

## Access-policy diagnosis, local images and CSV guidance

Update the Python 3.14 environment first. Protego 0.6.0 is now a core dependency for robots wildcard/specificity handling; its version is pinned because diagnostic reporting inspects the winning rule. The app still starts without media/audio dependencies or local models.

```bash
.venv/bin/python -m pip install -r requirements.txt -r requirements-media.txt
./IMPORT_CREATURE_LIBRARY.sh --diagnose-commons \
  --scientific-name 'Tyrannosaurus' --report /tmp/commons-access.json
```

The diagnostic does not initialize or modify the app database, import content or generate audio. It uses a fresh temporary HTTP cache and writes only an explicitly requested report. The report identifies the complete requested URL/query, GET method, actual importer User-Agent, robots URL/status, winning user-agent group/rule, policy snapshot hash, whether the request was sent, and actual HTTP status for attempted requests. The ordinary importer also includes an `access_log` (latest 2,000 events); normal HTTP caches retain `robots-<sha256>.txt` snapshots. Robots and API responses are separate events: **a robots rejection means the API was never sent and has no HTTP status**, even if robots.txt returned 200. Proxy/transport failures are reported separately. Diagnostic temporary snapshots are removed when it exits; the report retains the matching rule and hash.

The requested endpoint is Wikimedia's documented [Action API](https://www.mediawiki.org/wiki/API:Main_page), `https://commons.wikimedia.org/w/api.php`, using `action=query`, `generator=search` and `prop=imageinfo`, as described by [API:Search](https://www.mediawiki.org/wiki/API:Search) and [API:Imageinfo](https://www.mediawiki.org/wiki/API:Imageinfo). GET is supported; this is not an HTML search scrape. Wikimedia provides [API etiquette](https://www.mediawiki.org/wiki/API:Etiquette) and a [User-Agent policy](https://foundation.wikimedia.org/wiki/Policy:Wikimedia_Foundation_User-Agent_Policy) for programmatic clients. That does not establish that this importer can fetch a particular URL under your instruction to honor robots.

The [published Wikimedia deployment template](https://github.com/wikimedia/operations-mediawiki-config/blob/38b99ce210bb6d2e09319dce76848f74c5fc90b3/robots.txt#L148) contains:

```text
User-agent: *
Allow: /w/api.php?action=mobileview&
Allow: /w/load.php?
Disallow: /w/
```

The broad `/w/` rule covers our `action=query` image request. The mobileview exception is a different API operation; it does not authorize image search. Wikimedia's deployment script appends per-wiki rules, so the actual fetched Commons policy remains authoritative. This source-template inspection explains the reported rejection but is not a capture of your server's live robots.txt. Cloud access is still blocked by the proxy before robots retrieval; no live Commons HTTP status or site-specific winning rule is claimed here. Run the diagnostic above on the Ubuntu server to capture that distinction precisely.

The importer checks the **same actual identity** used on the wire, handles the most specific matching group/rule, and keeps access fail-closed when policy is unavailable. A custom `BBS_IMPORT_USER_AGENT` must start with `BedtimeBattleStoriesImporter/`; add a truthful version/contact, for example `BedtimeBattleStoriesImporter/1.0 (+https://YOUR-CONTACT-PAGE)`. Do not substitute a browser identity. The code does not switch verbs, actions, hosts or paths to evade a prohibition, and does not reinterpret API documentation as permission to ignore robots.

Its original Commons file page, download URL, exact described taxon, creator, supported license and matching license URL must be present. A filename alone remains insufficient.
